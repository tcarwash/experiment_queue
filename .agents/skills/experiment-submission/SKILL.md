---
name: experiment-submission
description: Use when a user wants an agent to design, prepare, validate and submit a pinned distributed research experiment through GitHub Issues.
---

Read `AGENTS.md`, `docs/agents/REPOSITORY_BOUNDARIES.md` and `docs/agents/EXPERIMENT_AUTHORING.md`, then verify the target research checkout's Git remote and read its `AGENTS.md`. **Write experiment-specific scripts, harnesses, fixtures and docs in their owning source repository** (for DORC-owned examples, `tcarwash/dorc_experiments`; for the RFSim common-suite executable, `tcarwash/RFSim`), not in this framework repo. Use `tcarwash/experiment_queue` read-only to validate the manifest or run the queue unless a separate framework change is explicitly requested. Keep cross-repository changes in separate commits and PRs. Pin the full pushed SHA, select the minimum required capability and approved image/adapter, write the single fenced JSON manifest and validate it. Use `gh issue create` only when authorized. Mark `experiment-ready` only when source, hardware and image eligibility have been checked or explicitly approved. Return the issue URL and expected evidence; do not claim the experiment has run unless it has.
